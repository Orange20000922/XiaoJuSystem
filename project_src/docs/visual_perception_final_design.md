# 动态视觉感知模块 — 最终设计方案

## 1. 方案概述

本文档为 `dynamic_visual_perception.md` 中提出的动态视觉感知模块的**最终技术决策记录**，基于对该文档中多个设计选项的分析与取舍，确定了各模块的具体实现路径。

核心原则不变：**本地做轻量实时筛选，云端做复杂语义理解。**

---

## 2. 最终技术选型

### 2.1 帧差 / 事件检测：MOG2 自适应背景模型

**决策：放弃简单帧差法，采用 OpenCV MOG2（Mixture of Gaussians）背景减除器。**

#### 问题背景

简单帧差法（当前帧 vs 上一帧做 absdiff）无法区分以下情况：

- 缓慢光照漂移（无意义但像素值持续偏移）
- 突然开灯（前几帧有意义，之后应被吸收为新背景）
- 传感器噪声导致的零散像素闪烁

这些噪声和有意义变化在**幅度**上可能重叠，但在**空间分布**和**时域特征**上不同：

| 特征 | 噪声 | 有意义变化 |
|------|------|-----------|
| 空间分布 | 全局均匀（光照）或零散孤立点（传感器） | 局部聚集（人、物体） |
| 时域持续性 | 单帧闪烁或极缓慢漂移 | 突变后持续存在 |
| 频率特征 | 高频抖动或极低频漂移 | 中频（动作、进入画面） |

#### MOG2 为何能解决

MOG2 对每个像素维护一个高斯混合模型作为背景表示：

- **渐变光照** → 背景模型自动漂移跟随，不触发前景检测
- **突然开灯** → 前几帧检测为前景（有意义事件），随后被吸收为新背景
- **人进入画面** → 持续检测为前景，因为像素分布与所有背景高斯不匹配
- **性能**：CPU 毫秒级，与简单帧差法同数量级

#### 额外过滤层

在 MOG2 输出之上，增加两级后处理：

1. **形态学操作**：先腐蚀（去除孤立噪声点），再膨胀（填充目标区域内空洞）
2. **连通域面积过滤**：忽略面积过小的连通域（阈值可调，建议初始值 ≈ 画面面积的 0.5%）
3. **时域投票**：连续 N 帧中至少 M 帧触发才认定为有效事件（建议 N=3, M=2）

### 2.2 关键帧筛选：三信号加权融合 + 峰值检测

**决策：采用多信号加权融合方案，而非单一指标（L2 距离、熵差、面积占比）。**

#### 预处理

在计算帧差信号之前，对每帧做 **5×5 高斯模糊**，消除传感器噪声对差分结果的干扰。

#### 三个互补信号

| 信号 | 计算方式 | 捕捉能力 | 权重 |
|------|---------|---------|------|
| S1：前景面积占比 | MOG2 输出的前景 mask 中非零像素占比 | 多大区域在变化 | 0.5 |
| S2：灰度直方图距离 | 当前帧与参考帧的 Bhattacharyya 距离 | 全局场景切换 | 0.2 |
| S3：边缘密度变化率 | Canny 边缘像素密度帧间差值 | 结构性变化（人/物体进出） | 0.3 |

三个信号的互补关系：

| 场景 | S1(面积) | S2(直方图) | S3(边缘) | 融合结果 |
|------|---------|-----------|---------|---------|
| 人进入画面 | 高 | 中 | 高 | 高 |
| 开灯 | 前几帧高后降低 | 高 | 低 | 中高（合理） |
| 摄像头噪声 | 低 | 低 | 低 | 低 |
| 人挥手 | 局部高 | 低 | 中 | 中 |
| 场景切换 | 高 | 极高 | 高 | 极高 |

#### 融合公式

```
s1, s2, s3 = sigmoid_normalize(S1), sigmoid_normalize(S2), sigmoid_normalize(S3)

change_score = 0.5 * s1 + 0.2 * s2 + 0.3 * s3

# 时域指数移动平均平滑
smoothed_score = α * change_score + (1 - α) * prev_smoothed_score
# α 建议 0.3（偏平滑，减少单帧抖动）
```

#### 峰值检测与选帧

1. 维护 1 秒滑动窗口
2. 在 smoothed_score 序列中寻找**局部极大值**
3. 过滤掉低于全局阈值的极大值（建议初始阈值 0.15）
4. 峰值附近选帧：同一峰值区间内取**拉普拉斯方差最大**的帧（最清晰）
5. 峰值间最小冷却间隔 0.5 秒，避免连续提交相似帧

#### 为何不用插值求导

理论上可以将离散 change_score 插值为连续函数再求导找极大值，但：

- 离散序列上的局部极大值检测已经等价于求导找零点
- 一阶差分 `score[t] - score[t-1]` 即可捕捉变化速率
- 插值引入额外计算和参数，无实际收益

#### 为何不用单一指标

- **L2 欧氏距离**：对全局光照变化极度敏感，轻微曝光调整即产生巨大值
- **图片熵差**：对光照同样敏感，且计算成本高于帧差
- **变化面积占比**：无法区分"大面积微弱变化"和"小面积剧烈变化"
- **SSIM**：对光照鲁棒，但计算量约为简单帧差的 10 倍

多信号融合继承了情绪系统中 BERT+LLM 融合的设计哲学：多个互补弱信号 > 单一强信号。

### 2.3 实现语言与性能架构

**决策：Python + OpenCV，不使用 C++/Rust。**

#### 理由

```
视频解码 → 帧差/事件检测 → 关键帧筛选 → Vision LLM API
  ~5ms       ~1-3ms            ~0.1ms       ~500-2000ms
```

- 本地处理总计约 10ms/帧，远低于 30fps 的 33ms 帧间隔，不构成瓶颈
- Python OpenCV 内部已调用 C++ 后端，非纯 Python 循环
- 瓶颈在 Vision LLM API 调用（秒级），优化本地处理无端到端收益
- 与现有系统（agent_loop.py、audio_pipeline.py 等）保持技术栈一致
- 真正需要加速时可用 `cv2.UMat`（OpenCL 加速）或将瓶颈函数编译为 C extension

#### 流水线架构

采用多线程生产者-消费者模式：

```
线程1 (Producer):   cv2.VideoCapture 逐帧采集 → bounded 帧队列
线程2 (Detector):   从队列取帧 → MOG2 + 三信号计算 → 写入事件缓冲区
线程3 (Selector):   缓冲区峰值检测 → 选关键帧 → 打包
线程4 (Uploader):   批量提交 Vision LLM（异步等待响应）
```

- 帧队列设上限（建议 5），防止解码速度超过处理速度时内存膨胀
- 线程间通过 `queue.Queue`（线程安全）通信
- Vision LLM 调用用 `ThreadPoolExecutor` 异步化，不阻塞检测线程

#### 关于实时流 vs POST 上传

实时陪伴场景使用 `cv2.VideoCapture` 直接读摄像头流，逐帧处理。POST 上传视频适用于离线分析场景，不作为主路径。

## 3. 与主系统的集成

### 3.1 集成路径

遵循 `dynamic_visual_perception.md` 第 6.4 节的建议，按复杂度逐步接入：

**第一阶段（MVP）：视觉结果作为 AgentEvent 送入 AgentLoop**

```python
# 视觉模块输出 → 包装为 AgentEvent
loop.push(AgentEvent(
    type="visual",
    content="[视觉事件] 用户回到座位",
    metadata={"confidence": 0.82, "frame_id": 147}
))
```

这是最低风险的接入方式，复用现有事件循环，不改动主对话链路。

**第二阶段：高置信视觉信号注入情绪状态机**

- 微笑 → valence +0.15（弱正向刺激）
- 皱眉/困惑 → valence -0.1（弱负向刺激）
- 突然动作 → arousal 增强
- 坚持"弱刺激"原则，视觉信号不压倒文本/语音情绪判断

**第三阶段：压缩后的视觉观察写入长期记忆**

- 只写入稳定行为模式或高情绪显著事件
- 不写入逐帧原始事件，避免污染 L3/L4 召回质量

### 3.2 Vision LLM 调用策略

筛选出的关键帧发送给已有的 Vision LLM（GLM-4V），输出三层结构：

1. **事实层**：用户坐在桌前 / 画面中出现一本打开的书 / 用户离开座位
2. **弱解释层**：可能在阅读 / 可能刚结束当前动作
3. **记忆候选层**：用户在书桌前持续阅读，状态较平稳

避免直接输出强心理推断（"焦虑""压力大"等），这类结论仅作为低置信内部提示。

### 3.3 信号分流

| 用途 | 信号类型 | 注入方式 |
|------|---------|---------|
| 短期上下文提示 | 用户抬头、微笑、离开返回 | 注入主 LLM 当前轮次 |
| 情绪弱刺激 | 表情变化映射为 valence/arousal 微调 | 注入情绪状态机 |
| 长期观察 | 稳定行为模式、高显著事件 | 压缩后写入记忆系统 |

## 4. 分阶段实施计划

### 第一阶段：MVP

- MOG2 背景减除 + 高斯预处理
- 三信号加权融合 + 时域平滑
- 峰值检测 + 清晰度优选
- 多线程流水线（采集 → 检测 → 筛选 → 上传）
- Vision LLM 分析关键帧
- 结果包装为 AgentEvent 送入 AgentLoop

### 第二阶段：状态联动

- 面部检测（YuNet / OpenCV DNN）
- 粗粒度表情变化检测（smile / frown / neutral）
- 高置信视觉信号注入情绪状态机

### 第三阶段：选择性增强

- 根据实际数据评估是否需要轻量 CNN 二次筛选
- 评估是否引入本地时序模型
- 视觉观察压缩后写入长期记忆
- 根据性能数据决定是否需要 Rust/C++ 加速特定组件

## 5. 关键参数初始值

| 参数 | 初始值 | 说明 |
|------|-------|------|
| 高斯模糊核 | 5×5 | 预处理去噪 |
| MOG2 history | 500 | 背景模型学习速率 |
| MOG2 varThreshold | 16 | 前景判定阈值 |
| 形态学核 | 3×3 | 腐蚀/膨胀 |
| 连通域面积阈值 | 画面面积 0.5% | 过滤小区域 |
| 时域投票 N/M | 3/2 | 连续3帧中至少2帧触发 |
| 融合权重 w1/w2/w3 | 0.5/0.2/0.3 | 面积/直方图/边缘 |
| 时域平滑 α | 0.3 | 偏平滑 |
| 峰值检测阈值 | 0.15 | 归一化后的最低有效峰值 |
| 峰值冷却间隔 | 0.5s | 避免连续提交相似帧 |
| 滑动窗口 | 1s | 事件缓冲区时间跨度 |
| Vision LLM 调用频率上限 | 2次/分钟 | 成本控制 |
| 帧队列上限 | 5 | 防止内存膨胀 |
